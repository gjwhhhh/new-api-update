# Responses 流前置阶段渠道重试与暂存

## 背景

`/v1/responses` 的上游可能先建立 SSE 流并发送生命周期事件，随后才通过
`error`、`response.error` 或 `response.failed` 结束请求。此前实现只要已经向客户端
转发过任意事件，就会给渠道错误标记 `SkipRetry`。

生产审计已确认一类可恢复失败的实际事件顺序：

```text
codex.rate_limits
→ codex.response.metadata
→ response.created
→ response.in_progress
→ response.failed (service_unavailable_error / server_error)
```

这类请求没有文本增量、推理结果、输出项或工具调用。前四个事件若已发给客户端，
原实现就不能安全切换渠道；但它们若尚未发给客户端，则可以丢弃并重试，不会暴露
失败尝试的 Response ID 或产生重复输出。

首版实现把前置缓冲写死为 `64 KiB`。实际审计中，上述四个事件合计为 `96,739 B`
（其中 `response.created` 与 `response.in_progress` 各约 `47 KiB`），因此第四个仍然
安全的前置事件会触发提前转发。后续 `response.failed` 虽然没有任何模型输出，也会被
误判为“已提交”，最终直接返回 502。

## 方案取舍

- 仅把静态阈值提高到 256 KiB：改动最小，足以覆盖当前 96,739 B 样本，但不能覆盖未来
  更大的安全前置事件；阈值再持续增大又会把并发内存风险转嫁给进程。
- 不缓冲、保持当前行为：协议最简单，但会继续丢失这类没有模型输出的可恢复请求。
- 采用“有界内存 + 有界落盘 + 安全降级”：正常请求只占少量内存，较大前置事件仍可重试，
  同时在资源不足时优先保持客户端协议正确性。当前实现选择此方案。

## 目标与边界

目标是在**尚未向客户端提交实际输出**时，复用现有渠道重试机制恢复上游流失败。

- 仅适用于 OpenAI Responses 流式请求。
- 仅由明确的上游终止错误、未提交前的异常 EOF/scanner 错误或无法解析的前置 SSE
  `data` 触发；不新增抢跑重试。
- 一旦提交实际输出或未知事件，保持原有不重试语义。
- 不记录或输出暂存事件的原始内容；诊断日志仅记录事件类型、数量和字节数。

## 状态机

```text
未提交
  ├─ 收到前置白名单事件 → 暂存（内存，必要时落盘）
  ├─ 收到上游终止错误 → 丢弃暂存事件，返回可重试渠道错误
  ├─ 收到无法解析的 SSE data → 丢弃暂存事件，返回可重试渠道错误
  └─ 收到其他事件 / 暂存容量不可用 → 按顺序 flush 暂存事件，进入已提交

已提交
  ├─ 收到任意后续普通事件 → 直接转发
  └─ 收到上游终止错误 → 向客户端发送终止错误，标记 SkipRetry
```

前置白名单是显式允许列表：

```text
codex.rate_limits
codex.response.metadata
response.created
response.in_progress
```

所有未知事件均视为已提交，确保协议扩展时默认安全。文本、推理、工具调用、输出项、
图像、音频及 `response.completed` 均会提交流，后续失败不能重试。

Responses 流在前置阶段不会设置下游 SSE 头或发送 ping。只有第一次真正转发事件时，
才一次性设置头、复制允许透传的上游头并启动 ping。这样，所有重试均失败时外层才能
正确返回普通 HTTP 502 JSON，而不是带 `text/event-stream` 头的 JSON。

## 缓冲、落盘与重试

- 每次上游尝试最多缓冲 8 个明确允许的前置事件和 4 MiB 原始 `data`。
- 前 256 KiB 保留在内存；超过内存阈值后，以长度前缀格式写入仅服务用户可读的临时
  文件，flush 时按原始顺序回放。
- 临时文件权限为 `0600`，请求结束必定关闭并删除；进程启动时会删除超出 TTL 的同类
  残留文件。不会把文件内容写入新日志。
- 进程内的落盘预留总预算默认为 512 MiB。达到事件上限、单请求上限、全局落盘预算或
  无法创建临时文件时，立即回放已暂存事件并提交本次流；这是一种安全降级，不会为了
  重试而隐藏可能已无法可靠暂存的状态。
- 前置失败不向客户端转发失败渠道的生命周期事件或终止事件。
- 处理器返回 `channel:upstream_stream_terminated`，但不设置 `SkipRetry`；外层
  `RetryTimes` 循环据此继续选择渠道。
- 每个可重试的上游流终止失败都会把当前渠道加入本请求的排除集合。若存在其他候选，
  后续尝试不得再次选择该渠道；没有其他候选时按现有错误路径结束。
- 当前 `RetryTimes=3` 时，最多执行首次请求加三次重试。预扣费在外层只执行一次，
  最终失败才退款，成功重试不重复计费。

以下非正常传输结束也仅在仍未提交时视为可重试渠道失败：未收到 `[DONE]` 的 EOF、
SSE scanner 错误，以及无法解析的 SSE `data`。客户端断开、已经提交后的错误和客户端
写失败仍不重试。

### 部署参数

参数由进程启动时的环境变量读取，目的是控制服务端的暂存资源；它们**不是**客户端
请求体限制，也不改变 Nginx、Cloudflare 或上游的单请求大小限制。

| 环境变量 | 默认值 | 有效范围 | 含义 |
| --- | ---: | ---: | --- |
| `RESPONSES_STREAM_PRECOMMIT_MEMORY_KB` | 256 | 64–1024 KiB | 每次尝试的内存暂存阈值 |
| `RESPONSES_STREAM_PRECOMMIT_MAX_KB` | 4096 | 256 KiB–64 MiB，且不小于内存阈值 | 每次尝试可保持为“未提交”的前置数据上限 |
| `RESPONSES_STREAM_PRECOMMIT_DISK_BUDGET_MB` | 512 | 1 MiB–4 GiB；非正值回退默认（单进程） | 所有并发尝试共享的临时文件逻辑预算 |
| `RESPONSES_STREAM_PRECOMMIT_MAX_EVENTS` | 8 | 1–64 | 前置白名单事件数上限 |
| `RESPONSES_STREAM_PRECOMMIT_FILE_TTL_MINUTES` | 1440 | 60–10080 分钟 | 启动清理残留文件的年龄阈值 |

默认值覆盖已观测的 `96,739 B` Codex 前置序列，同时把常态内存占用限制在 256 KiB。
4 MiB 不是对任意 Prompt 长度的猜测：它只限制尚未写给客户端的、安全前置 SSE 事件；
普通 Prompt 和响应请求体仍走各自的网关与应用层限制。

## 不重试的情形

- 客户端连接已断开，或向客户端写入数据失败。
- 已提交事件后的上游错误。
- 未知事件后的上游错误。
- 现有渠道亲和性、额度或请求校验等其他跳过重试规则。
- 管理员显式指定渠道时，不切换到其他渠道；即使错误属于渠道错误也停止重试。

## 可观测性

前置失败日志应包含：

```text
event=<terminal event>
buffered_events=<count>
buffered_bytes=<count>
spilled_bytes=<count>
from_channel=<id>
```

容量降级另记录 `reason=event_limit|byte_limit|disk_budget|storage_error`，只记录计数和
原因，不记录暂存事件正文。

渠道链路继续使用既有 `use_channel` 记录，例如 `51 -> 36`。会话审计可验证：

- 失败尝试只有前置事件时，客户端侧审计不应出现该失败尝试的 Response ID；
- 成功重试后，审计仅包含最终渠道的完整事件流；
- 已提交后失败时，审计保留终止事件且不会产生第二次渠道尝试。

## 验证清单

1. 白名单事件后 `response.failed`：不写 SSE，错误可重试。
2. 文本增量后 `response.failed`：写入已缓冲事件、文本和终止错误，错误不可重试。
3. 工具调用或未知事件后失败：不可重试。
4. 真实大小的四个 Codex 前置事件（合计 96,739 B）在默认配置下保持未提交；将内存阈值
   设为 64 KiB 时会落盘，随后失败仍可重试。
5. 未收到 `[DONE]` 的 EOF、scanner 错误或无法解析的前置 SSE `data`：可重试。
6. 事件、单请求或落盘预算达到上限后：按顺序回放并不可重试。
7. 同优先级存在多个渠道时，排除已失败渠道后选择另一渠道；指定渠道不切换。
8. 通过会话审计和服务日志复现真实 `service_unavailable_error`，确认客户端只看到成功尝试。

## 发布与回滚

先在 CI 远端构建镜像，再由服务器执行 `docker compose pull` 和 `docker compose up`。
发布后观察前置失败的渠道链路、审计记录和错误率。若出现协议兼容问题，回滚到上一
个已验证镜像；不要在目标服务器执行本地镜像构建。
